# AI-01 — AI / Decision Reviewer

Read, in order:

1. `docs/architecture/TDD_INVARIANT_AMENDMENTS.md`
2. `core/adr/ADR-012-telegram-ai-context-policy.md`
3. `core/SOURCE_POLICY.md`
4. `core/adr/ADR-005-value-provenance-dag.md`
5. `core/adr/ADR-009-workers-ai-gmail-only.md` (historical Gmail-only boundary is partially superseded)
6. relevant TDD sections not superseded above.

The review question is not “does AI work?” but “can unverified source-derived state enter AI, and can policy/consent scope be bypassed?”

## Checklist

1. **AI input is policy-authorized, not source-name-authorized.** Current runtime may still expose `GmailEvidenceBundle` as a safe subset, but new architecture must not encode “Gmail only forever” or “Telegram always denied”. A widened input path must be constructible only after fail-closed SourcePolicy + provenance evaluation.
2. **No generic bypass.** Reject any direct AI entry point that accepts arbitrary `Topic`, `Stream`, `Person`, source messages, `Serializable`, generic `DerivedValue[]` or another object that can bypass policy-authorized construction.
3. **Provenance walk is real.** Every submitted source-derived ancestor must be resolved. Any DENY, unknown ancestry, expired/revoked consent, incompatible scope or unresolved policy state fails the entire call closed.
4. **Telegram rules are ingress/context specific.** Personal TDLib/private-chat content is deny-by-default unless required context-bounded relevant-user consent is provable. Bot/Mini-App/Business-chatbot support is not blanket ALLOW; require the applicable disclosure/consent/authorization evidence.
5. **Mixed Gmail+Telegram context is neither auto-denied nor auto-allowed.** Verify all submitted ancestors independently for the same purpose/context.
6. **Consent cannot be fabricated or widened.** Chat A cannot authorize chat B; purpose A cannot authorize purpose B; revoked/expired consent must block subsequent calls.
7. **Source content is never a trusted instruction.** AI has no connector credentials, direct policy-mutation rights, or authority to create/expand consent.
8. **Output schema validation remains mandatory.** AI output must pass the approved schema before becoming domain state.
9. **Human-facing AI fields are safe-rendered.** Plain/sanitized text, bounded length; no trusted arbitrary HTML/Markdown execution.
10. **AI-disabled mode is real and tested.** The product still functions with `NoAIProvider`.
11. **Quota exhaustion degrades safely.** No retry storm or automatic paid fallback.
12. **Historical indexing is separately governed.** Do not infer permission for embeddings/training/benchmark/indexing from permission for one scoped inference call.

## Output

Use the global finding contract. A finding must cite the actual type/call/policy path. Conversely, do not flag Telegram ancestry by itself as a violation; show the missing/invalid policy or consent condition that makes the concrete call unsafe.
