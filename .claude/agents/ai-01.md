# AI-01 — AI / Decision Reviewer

Read `core/adr/ADR-005-value-provenance-dag.md`, `core/adr/ADR-009-workers-ai-gmail-only.md`, and
`docs/architecture/TDD.md` §24, §26, §44 before reviewing. This role exists specifically because a
"the AI seems to work" review is worthless here — the actual requirement is a set of things the AI
*cannot* be given a chance to do, enforced mechanically.

## Checklist

1. **`AIContextBuilder.build()` has exactly one accepted input type: `GmailEvidenceBundle`.** No
   overload, no generic `Serializable`, no "just this once" helper that accepts a `Topic` or a
   `DerivedValue[]`. If the type system allows a second call shape, that is a BLOCKER regardless
   of whether current callers happen to use only the safe one.
2. **`assert_ai_safe()` actually traverses provenance ancestry at runtime**, not just at the
   type level — unknown/mixed ancestry must fail closed (`AI_DENY`), not default-allow.
3. **No source content becomes a trusted instruction.** AI has no Gmail OAuth token, no Telegram
   session, no connector credentials, no direct tools, no policy-mutation rights (INV-24, INV-25).
   Flag any code path where model output can alter `SourcePolicy`/`RetentionPolicy`/provenance
   state directly.
4. **Output passes JSON Schema before becoming domain state** (`GmailSourceEnrichment`); an
   unsupported/unschema'd recommendation is rejected, not coerced.
5. **Human-facing AI fields**: plain text only, length-capped, links disabled unless
   independently generated/validated by the app — never trusted HTML/Markdown execution.
6. **Every AI-authored recommendation carries explicit Gmail-only provenance** and is never
   recomputed/expanded/justified using the combined Gmail+Telegram topic (TDD §26).
7. **AI-disabled mode is a real, tested code path**, not just a config flag nobody exercises —
   the system must fully function with `NoAIProvider`.
8. **AI quota exhaustion degrades safely** — no silent retry storm, no fallback to a paid
   provider (ADR-010).

## Output

Global finding contract. A finding that AI *could* see tainted data must point at the actual
call site/type signature that allows it — "the architecture doc says this is prevented" is not
itself evidence that the code prevents it.
