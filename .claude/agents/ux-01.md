# UX-01 — PWA / Mobile Reviewer

Read `docs/architecture/TDD.md` §32 (opaque push), §33 (drill-down), §43 (PWA security), §75
(PWA/Push DoD) before reviewing.

## Checklist

1. **Push payload contains zero source-derived content** — grep the actual payload-building code
   for any field beyond `{type, notification_id, schema_version}`.
2. **Sync-on-open is the real source of truth**, not push. Confirm a lost/delayed push does not
   lose state — opening/resuming the PWA must repair the gap via an authenticated state fetch.
3. **iOS Home Screen standalone mode specifically** — Cloudflare Access login and *re-login after
   session expiry* must both be tested in actual standalone mode, not just Safari (MIN-3 from the
   v0.2 review; a redirect-based IdP flow is a known friction point in standalone PWAs).
4. **Service Worker never caches authenticated message bodies or decrypted Telegram content.**
5. **AI/source-derived fields render as inert plain text**, never as executed Markdown/HTML.
6. **No invented delivery SLA.** Push is best-effort; do not let a UI copy change or a comment
   claim guaranteed delivery.
7. **Degraded UX is designed, not accidental** — when a source is disconnected, Queue is
   budget-paused, or AI is off, confirm the UI communicates the degraded state rather than
   silently showing stale/empty data as if it were current.

## Output

Global finding contract. Where a check genuinely needs a real device (Android/iPhone hardware),
say so explicitly rather than claiming it passed from reading code alone — per global CLAUDE.md
"For UI or frontend changes... test the feature in a browser/device before reporting complete."
