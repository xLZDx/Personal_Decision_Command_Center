§3 How they were checked — and what the check missed

An agent's summary is a claim, not a fact, so all nine files were run through an independent validator importing the repository's real parsePathList, compilePattern and checkScope. For all nine: allowed_paths non-empty, every pattern compiles, no vacuous **, both mandatory authority exclusions present, and a probe of those two paths refused by every file.

And that check lied. It reported all nine "ok" while G8_MANIFEST_PROPOSAL.yaml was invalid YAML: an unquoted scalar containing : " parses as a mapping separator. The validator could not see it because the repository's manifest reader is a deliberately tiny YAML subset parser that walks only the two path blocks. So "validated against the real parser" was a claim broader than the check behind it — precisely the defect I look for in others. Prettier's full parser found it. Fixed.

§4 BLOCKER: the test-deletion guard is blind

scripts/verify/check-test-deletion.mjs exists so a PR cannot quietly delete or disable tests. Both of its halves are restricted to .test.ts: 

const TEST_FILE = /(^|\/)tests\/.*\.test\.ts$|\.test\.ts$/;
git diff -U0 BASE...HEAD -- '*.test.ts'

Both branches of the alternation end in .test.ts, and the second pass is pinned to the same pattern. The project's test corpus looks like this:

64 of 101 tests are unprotected — and they are exactly the three suites that enforce governance. A PR may delete gate-scope.test.mjs outright and the guard will print "no tests removed or skipped".

Why it survived matters more than the bug. This guard is one of the three refusal controls the remediation plan requires to be demonstrated on a real PR. None of the three ever were: they are evidenced by unit tests only, and those were written against .test.ts fixtures. One run against the repository's real corpus would have exposed it immediately.

§7 What only the operator can decide

Whether require_code_owner_review stays off. It is off today, which is why CODEOWNERS is decoration. It cannot simply be switched on: with one account, PR author = code owner = required reviewer, and GitHub forbids approving one's own PR.
