GPT-PM's ruling on the G2 architecture

Full text preserved in core/DECISION_LOG.md and in governance/plans/G2_PIPELINE_ARCHITECTURE_PROPOSAL.md's Status section. Broken down below.

Blocker§2 · reconciler schema

Rejects the pure processing_outbox-native schema

The architect agent's proposal (add DONE/TERMINAL states purely to processing_outbox) breaks ADR-006's own separation: processing truth lives in ingest_events.state, transport truth lives separately in processing_outbox.state. It fails the case where the event has already gone terminal while the outbox row still reads DISPATCHED.

Required: the eligibility predicate must still inspect ingest_events.state joined to the due outbox row, with the index proven index-covered (EXPLAIN QUERY PLAN + volume test). A transport-side terminal state may exist as an optimization, never as the sole correctness mechanism.
Blocker§3 · attempt cap

Rejects the proposed DLQ transition

Unconditionally claiming rows and partitioning them afterward is not what the spec requires: the transition to DLQ must be one atomic transaction together with the very processing failure that exhausts the attempt budget, not a separate reconciler pass that "discovers" an already-exhausted event.

Required: the transaction that pushes attempt_count to MAX_PROCESSING_ATTEMPTS must itself atomically set DLQ and insert the dead_letter_events row. Separately: queue-visibility expiry must not consume processing-attempt budget.
Blockernew finding

Stale-PROCESSING recovery is unspecified

PROCESSING exists in the event state model, but the reconciler as specified only selects ACCEPTED/RETRYABLE_FAILED. A consumer that crashes between entering PROCESSING and its next transition leaves that event permanently invisible to the reconciler. None of the four agents or the audit caught this.

Required: a bounded processing lease/claim with expiry and CAS semantics (or equivalent), coexisting with queue redelivery and preserving idempotent domain writes.
Confirmed§4 · services/resolver

Deferring candidate resolution to G5 is correct

PLAN_MASTER_GATES.md assigns Identity/Project/Stream/Topic resolution to G5. G2 may build reusable bounded-query/quota primitives and a resolver-facing interface, but must not implement candidate scoring inline in services/processor.

Major§5 · devices table

Drop devices from migration 0001

The migration's own header argues against creating schema ahead of the gate that needs it, then does exactly that for G7's benefit. No G2 dependency justifies the exception.

Required: remove it from 0001_ingest_outbox.sql; G7 introduces it in its own migration.
Ruling§5 · provenance DAG

Runtime multi-hop now, persistent DAG later

G2 must implement and test generic transitive ancestry traversal (ADR-005 already owes this), but need not invent persistent ancestry tables for G5/G6 domain nodes. provenance_event_id should reference ingest_events(event_id) directly.

Confirmed, broadened§7 · provenance fail-open

The isAiSafe() gap is real — but the fix must be wider

Flipping !== 'DENY' to === 'ALLOW' alone is insufficient. Discriminated node schemas (source-event / static-config / derived) are needed so an arbitrary derived object cannot become a trusted root merely via an empty provenance: []; policy fed into sourceEventNode() must come from the validated path, never an arbitrary caller-supplied value.

Major§7 · telegram + ALLOW

Needs structural enforcement, not only a CHECK

Beyond forbidding telegram + ALLOW in source_policies, composite foreign keys should bind an event's source to both its account's and its policy's source — an application-level invariant alone is not enough.

Major§7 · idempotency collision

Needs a contract and migration change, not just the key function

The TDD already names a fourth key field, source_version_if_needed, that the implementation never added. GPT-PM confirmed the finding and added independent corroborating evidence from Telegram itself (TDLib: message_id stable, edit_date changes on edit).

Required: add a version field to the normalized-event contract and the D1 schema, and fold it into idempotency for versioned events.
Majornew finding

ProvenanceValueSchema doesn't match the TDD

The frozen spec's ProvenanceValue<T> carries sensitivity, created_at, derivation_version across strings/numbers/datetimes/ booleans/enums/aggregates; the shared schema hard-codes a non-empty string and omits those fields.

Required: either a generic/discriminated implementation matching the TDD, or an explicit TDD erratum.

Accepted without objection

  • The atomic single-statement budget-counter upsert.
  • A hard MAX_ROUTING_HINTS cap — 16 treated as provisional pending a quota-harness measurement.
  • Never treating an in-Worker Date.now() read as CPU evidence.
