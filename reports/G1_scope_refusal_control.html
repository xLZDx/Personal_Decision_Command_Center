01

The control that was missing

The repository has a check whose job is to refuse a PR touching a path outside the manifest the operator approved. Yesterday it passed for the first time in the project's history. That closed one gap and opened its mirror image: the mechanism had been observed only in the direction that lets work through.

Every earlier refusal was at a different step. Until today, every recorded refusal happened at the hash step — because no approved hash existed yet. The hash step fails before scope is evaluated at all. That proves the ordering and says nothing about the scope rule itself. A guard seen only saying yes is not known to say no.

The instrument was real, not synthetic

.gitignore covers .env and .env.* but not .dev.vars — the filename Wrangler reads local secrets from. The gap was found earlier and deferred precisely because .gitignore is outside G1's scope: the manifest g1.yaml names it in its own "DELIBERATELY EXCLUDED" list. So the path is out of scope by the manifest's explicit reasoning, not by an accidental omission. And it is deliberately not one of the four forbidden_paths — those carry their own refusal, and what was being tested here was the ordinary one.

So commit 98716b3 genuinely closes the gap, and doubles as the instrument. The next commit reverts it: the refusal is the deliverable, the file change is the apparatus.

A report in the same PR claimed the opposite

GPT-PM's round-1 MAJOR was right. The same PR carried a report pair saying the scope step had been observed "passing only" and that both checks "pass on every commit". The first was being disproved by that very PR. The second erases deliberate failures: a head that violates policy is supposed to fail.

Two incompatible statements of G1's state, shipped together

A report is a durable artifact. A claim that was true when written and false by the time it merges is still a false claim on main. This is exactly the defect class the report itself is about.

Fixed in both languages, three edits each. The "passing only" sentence is not deleted — it is bounded to the block it describes, with a dated paragraph beneath it naming the run. History stays visible, current status is corrected. The row in the remaining-items table moves to done.

06

Three questions that are yours to decide

The three remaining negative controls are blocked on authority, not on effort. I put both contested questions to GPT-PM and record its answer as an opinion I weighed, not as permission: under §23 a reviewer's prohibition is not a prohibition, and its permission is not authority. So the questions are yours either way.

What is needed from you

  1. Hash-mismatch control. The cleanest route touches no file at all: temporarily set the variable GATE_MANIFEST_APPROVED_HASH_G1 to any wrong value, re-run the Governance check on any open PR, confirm it fails at step 5 with Manifest hash mismatch for G1, and restore the previous value e95bfcf5e97580d1e9f076de47f6da4e4b7e31bd5e57b162c5c4cdfdf43ed162. The manifest file is never modified, not even for a second.
  2. Forbidden-paths control. This needs a branch that genuinely touches one of the four authority paths. The safest is governance/operator-approvals/README.md: the edit is additive, the directory is yours anyway, and it is not a manifest — so the hash step passes and the refusal comes from the scope step with its distinct forbidden_paths message. The manifest itself will not do: editing it fails the hash step first and masks the thing being tested.
  3. The deletion half of the test guard. This needs a PR whose diff deletes a *.test.mjs file that exists on main — for example tests/policy/codeowners.test.mjs. The PR is opened purely to be refused and then closed unmerged; main is never touched. I am not doing this myself: deleting a file is yours under §20 with no exception, and reverting it later does not create one.

None of the three costs money or changes anything irreversibly. But each requires the action to be taken by someone who is not the gate's implementer — otherwise the control is checking itself.
